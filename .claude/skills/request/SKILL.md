# /request — math-worksheet 요청 오케스트레이터

## 역할

이 스킬은 바로 구현하지 않는다. 사용자의 요청을 이 레포 구조에 맞게 분류하고, 먼저 `/analysis`로 안전 점검을 만든 뒤, 사용자 확인을 받은 다음 `/develop`로 넘긴다.

```text
/request
→ /analysis
→ 사용자 확인
→ /develop
→ 검증
→ 완료 보고
```

항상 한국어로 설명한다. 사용자는 비개발자일 수 있으므로 “어떤 파일을 왜 보는지”를 쉬운 말로 말한다.

## 요청 분류

| 요청 유형 | 기존 스킬에서 흡수한 내용 | 처리 |
|---|---|---|
| 새 학습지 추가 | `new-worksheet/SKILL.md` | generator 작성, catalog 등록, validate 검증까지 분석 후 진행 |
| 선수학습 진단지 추가 | `new-diagnostic/SKILL.md` | 선수학습 항목을 4문항씩 압축해 A4 2단 진단지로 구성 |
| 새 학년·학기 추가 | `new-grade/SKILL.md` | CURRICULUM 확인, generators/catalog 스캐폴드, catalog.js 등록 |
| 카탈로그 점검 | `audit-catalog/SKILL.md` | `audit.mjs`, `validate.mjs` 결과를 보고하고 필요한 수정 제안 |
| 기존 학습지/화면 버그 수정 | Codex `request/analyze/develop` | 영향 파일을 읽고 안전 판정 후 구현 |
| 문서/스킬 수정 | 이 파일군 | `.claude/skills` 문서 구조를 유지하며 수정 |

## 진입 경로

### 1. 이전 분석 기록이 있는 경우

입력에 `context/sessions/` 경로가 있으면:

1. 해당 기록을 읽는다.
2. `요구사항 원문`, `판정`, `기술 요구사항`, `검증 계획`을 요약한다.
3. 사용자에게 이대로 진행할지 확인한다.
4. 사용자가 동의하면 `/develop context/sessions/...md` 흐름으로 진행한다.

보고 형식:

```text
이전 분석 기록을 확인했습니다.
- 요청: ...
- 판정: ...
- 작업 항목: ...
- 확인 방법: ...

이대로 진행할까요?
```

### 2. 새 요청인 경우

1. 요청을 위 표의 유형으로 분류한다.
2. 구현하지 말고 `/analysis` 흐름을 먼저 적용한다.
3. 분석 보고서를 보여주고 판정별로 묻는다.

```text
✅ 안전: "이대로 진행할까요?"
⚠️ 주의 필요: "이 점을 감안하고 진행할까요?"
❌ 위험: 안전한 대안을 먼저 선택받기
```

## 확인 규칙

- 사용자 확인 없이 `/develop`로 넘어가지 않는다.
- 사용자가 “분석만”, “검토만”, “계획만” 원하면 구현하지 않는다.
- 아주 작은 읽기 전용 질문은 바로 답해도 된다.
- 커밋/푸시는 사용자가 명시적으로 요청하거나 승인한 경우에만 한다.

## 완료 보고

`/develop`가 끝나면 짧게 보고한다.

```text
✅ 작업 완료!
- 새로 만든 파일: ...
- 수정한 기존 파일: ...
- 확인한 내용: ...
- 남은 주의점: ...
```
