# 분석 기록: worksheet 구성과 진단지/선수학습/본단원 구분 UX 검토

- **일시**: 2026-05-07
- **요구사항 원문**: 현재 worksheet 구성, 특히 한 단원 안에 진단지/선수학습/본단원이 모두 들어 있는 구조가 최상인지 묻고 싶다. 새로 만들기 버튼 옆에 진단/선수학습/본단원 버튼을 두는 것이 좋은지 디자이너적 관점/엔지니어적 관점에서 철저하게 분석해 달라.
- **판정**: ⚠️ 조건부 안전

## 요구사항 해석

- 이번 요청은 구현보다 제품 구조와 UI 방향을 검토하는 요청이다.
- 실제 코드 수정 없이 현재 구조를 확인하고, 버튼/필터 추가 여부를 판단한다.
- 필요하면 이후 구현 가능한 작업 항목으로 나눈다.

## 현재 상태

현재 앱은 상단 컨트롤바에서 다음 순서로 선택한다.

1. 학년·학기
2. 단원
3. 연습지
4. 쪽수
5. 문제 수
6. 글자 크기
7. 새로 만들기 / 이어 붙이기 / 정답 보기 / 조건부 단 선택 / 인쇄

연습지 드롭다운은 `populateWorksheetSelect()`에서 같은 단원의 모든 항목을 순서대로 넣는다. 표시명은 `[진단지]`, `[선수학습]`, `[본단원]` 접두어로 구분한다.

카탈로그 데이터는 이미 `section` 필드로 구분되어 있다.

- `진단지`: `section: '진단지'`, `kind: 'diagnostic'`
- `선수학습`: `section: '선수학습'`
- `본단원`: `section: '본단원'`

5학년 1학기 기준 항목 수:

| 단원 | 전체 | 진단지 | 선수학습 | 본단원 |
|---|---:|---:|---:|---:|
| 1단원 자연수의 혼합계산 | 29 | 1 | 13 | 15 |
| 2단원 약수와 배수 | 9 | 1 | 2 | 6 |
| 3단원 규칙과 대응 | 5 | 0 | 0 | 5 |
| 4단원 약분과 통분 | 11 | 1 | 2 | 8 |
| 5단원 분수의 덧셈과 뺄셈 | 18 | 1 | 6 | 11 |
| 6단원 다각형의 둘레와 넓이 | 12 | 1 | 2 | 9 |

따라서 현재 구조는 작은 단원에서는 충분하지만, 1단원/5단원처럼 항목이 많은 단원에서는 연습지 드롭다운이 길어져 탐색 부담이 생긴다.

## 디자이너적 판단

### 현재 구조의 장점

- 학년·학기 → 단원 → 연습지 흐름이 단순하다.
- `[진단지]`, `[선수학습]`, `[본단원]` 라벨 덕분에 사용자가 현재 항목의 성격을 알 수 있다.
- 별도 화면 전환이 없어서 인쇄 도구답게 빠르게 쓸 수 있다.

### 현재 구조의 한계

- 5-1 1단원은 한 드롭다운에 29개 항목이 들어가므로 처음 보는 사용자에게 길다.
- 선생님/학부모의 실제 의도는 보통 "진단부터 할지", "부족한 선수학습을 뽑을지", "본단원 연습지를 뽑을지"로 시작한다. 현재 UI는 이 의도를 먼저 묻지 않고 긴 목록에서 직접 찾게 한다.
- `[진단지]` 항목이 맨 앞에 있어도, 사용자는 진단지와 선수학습과 본단원이 한 단계의 동등한 선택지인지, 순서가 있는 학습 흐름인지 바로 이해하기 어렵다.

### "새로 만들기" 옆 버튼 배치의 문제

`새로 만들기` 옆은 실행 버튼 영역이다. 여기에 `진단/선수학습/본단원` 버튼을 두면 사용자가 다음처럼 오해할 수 있다.

- 진단 버튼을 누르면 바로 진단지가 생성되는가?
- 선수학습 버튼을 누르면 기존 학습지 선택이 바뀌는가?
- 본단원 버튼은 필터인가, 생성 명령인가?

디자인 관점에서는 `진단/선수학습/본단원`은 실행 명령이 아니라 "연습지 목록을 좁히는 기준"에 가깝다. 따라서 실행 버튼 옆보다는 `연습지` 드롭다운 바로 근처에 두는 편이 자연스럽다.

## 엔지니어적 판단

### 구현 난이도

이미 모든 catalog item에 `section`이 있으므로, 구분 UI를 만드는 것은 비교적 안전하다.

필요한 기본 변경:

- `app/worksheet.html`: `연습지` 선택 근처에 학습 단계 segmented control 추가
- `app/js/app.js`: 현재 선택한 section filter 상태 추가, `populateWorksheetSelect()`에서 필터링
- `app/css/worksheet.css`: 컨트롤 스타일과 모바일 대응

카탈로그 데이터 구조 자체는 바꿀 필요가 없다.

### 주의할 점

- 어떤 단원은 `진단지`와 `선수학습`이 없다. 예: 5-1 3단원, 1~4학년 일부 구현 단원
- 필터 버튼을 항상 보이면 빈 버튼이 많아지고, 숨기면 단원 변경 시 컨트롤 모양이 조금 바뀐다.
- 현재 `preferredId` 유지 로직과 맞물려, 필터 변경 후 선택 가능한 첫 항목으로 안전하게 이동해야 한다.
- 본단원 항목에 출처 태그를 붙이지 않는 기존 규칙은 유지해야 한다.
- 컨트롤바가 이미 꽤 길다. 특히 `#worksheetSelect`가 `min-width: 420px`이고 모바일에서는 세로로 쌓이므로 버튼을 잘못 넣으면 화면이 답답해진다.

## 추천안

### 1순위: 연습지 드롭다운 앞/위에 "학습 단계" segmented filter 추가

권장 형태:

```text
학습 단계  [전체] [진단지] [선수학습] [본단원]
연습지    [ ... ]
```

또는 공간을 아끼려면:

```text
연습지  [진단지] [선수학습] [본단원]  [드롭다운]
```

권장 기본값은 `전체` 또는 `본단원` 중 선택이 필요하다.

- `전체`: 현재 동작과 가장 비슷해서 회귀가 적다.
- `본단원`: 실제 사용 빈도가 높을 가능성이 크지만, 진단지 발견성이 낮아질 수 있다.

분석상 추천은 `전체`를 기본으로 두고, 항목 수가 많은 단원에서 사용자가 직접 좁히게 하는 방식이다. 다만 진단지 중심 흐름을 더 강조하려면 5학년 1학기처럼 진단지가 있는 단원에서는 `진단지`를 첫 진입값으로 둘 수도 있다.

### 2순위: 드롭다운 안에 `<optgroup>`으로 구획만 나누기

버튼을 늘리지 않고 `진단지`, `선수학습`, `본단원` 그룹 제목만 넣는 방법이다.

장점:

- UI가 거의 늘어나지 않는다.
- 구현이 더 작고 안정적이다.
- 현재 "한 드롭다운에서 고른다"는 흐름을 유지한다.

단점:

- 29개 항목을 줄여 주지는 못한다.
- 사용자가 "본단원만 보고 싶다" 같은 빠른 필터링은 할 수 없다.

### 비추천: 새로 만들기 버튼 옆에 세 버튼 추가

이 위치는 동작 버튼 자리라서 필터 성격의 버튼과 섞이면 의미가 흐려진다. 컨트롤바도 더 복잡해진다. 꼭 버튼을 쓴다면 `새로 만들기` 옆이 아니라 `연습지` 선택 근처에 두는 것이 맞다.

## 점검 결과

| 점검 항목 | 결과 | 근거 |
|---|---|---|
| 기존 약속 | ✅ | section 필드를 이용하면 catalog/generator/template 계약을 깨지 않는다. |
| 연결 관계 | ✅ | UI 필터는 app 계층에서 처리하면 된다. renderer/generator가 UI를 알 필요가 없다. |
| 데이터 모양 | ✅ | 기존 학습지 ID, `from`, `kind`, `section` 의미를 유지할 수 있다. |
| 과거 기록 | ⚠️ | "선수학습 칩 패널 금지"와 충돌하지 않게 source chip이 아니라 학습 단계 필터로만 설계해야 한다. |
| 사용자 흐름 | ⚠️ | 필터 기본값을 잘못 잡으면 기존처럼 첫 항목이 바로 생성되는 기대가 달라질 수 있다. |
| 되돌리기 어려움 | ✅ | 정적 HTML/CSS/JS 변경이며 배포 설정, 의존성, 데이터 삭제가 없다. |

## 제시한 대안

- **A안: 그대로 유지** — 구현 없음. 작은 단원에서는 충분하지만 5-1 1단원처럼 큰 단원에서 탐색 부담이 남는다.
- **B안: `<optgroup>`만 추가** — 가장 안전하고 작다. 목록이 길다는 문제는 완전히 해결하지 못한다.
- **C안: 학습 단계 segmented filter 추가** — 사용자 의도와 가장 잘 맞고 확장성도 좋다. 단, 위치와 기본값을 신중히 정해야 한다.
- **D안: 새로 만들기 옆에 버튼 추가** — 실행 버튼과 필터 버튼이 섞여 비추천이다.
