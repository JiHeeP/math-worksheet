# 분석 기록: 5학년 1학기 단원별 선수학습 진단지 추가 계획

- **일시**: 2026-05-06
- **요구사항 원문**: 5학년 1학기 각 단원별로 선수학습 진단지를 추가하고자 함. 목적은 선수학습 진단. 선수학습의 내용을 각각 4문항씩 담은 문제가 인쇄되어 있는 A4. 진단지 구성은 2단. 없으면 진단지 없음. 한 단 24문항, 한 장 48문항, 48개가 넘어가는 경우 2장 배치도 가능. 최대한 배치를 줄여 배치하기. 계획을 먼저 세워라.

## 요구사항 해석

- 5학년 1학기 각 단원마다 기존 `선수학습` 항목을 진단 문항 원천으로 삼는다.
- 선수학습 항목 1개당 4문항을 만든다.
- 선수학습 항목이 없는 단원은 진단지 학습지를 만들지 않는다.
- 진단지는 A4 2단 구성이다.
- 한 단 최대 24문항, 한 장 최대 48문항으로 잡는다.
- 총 문항이 48개를 넘으면 2장 이상 허용한다.
- 목표는 페이지 수 최소화다.

## 왜 새 진단지 렌더러가 필요한가

기존 학습지는 연습용이라 세로셈, 나눗셈, 분수 풀이, 개념 카드처럼 문제별 공간이 크다. 이를 그대로 2단 24문항에 넣으면 A4 한 장에 들어가기 어렵다.

따라서 진단지는 기존 선수학습 generator를 재사용하되, 화면 표현은 진단용으로 짧게 변환하는 방식을 권장한다.

예:

- 세로셈형 `34 + 58` → `34 + 58 = □`
- 세로 나눗셈형 `96 ÷ 4` → `96 ÷ 4 = □`
- 나머지 있는 나눗셈 → `97 ÷ 4 = □ ... □`
- 기존 가로식/분수식 → 기존 HTML을 최대한 재사용하되 compact CSS 적용

이렇게 해야 “한 단 24문항, 한 장 48문항” 기준에 가까워진다.

## 설계안

### 권장안: `kind: 'diagnostic'` 전용 렌더러 추가

1. 5-1 카탈로그에서 단원별 선수학습 항목을 모은다.
2. 선수학습이 1개 이상인 단원에만 `[진단지] 선수학습 진단지` 항목을 추가한다.
3. 진단지 항목은 `{ kind: 'diagnostic', sources: [...] }` 형태로 기존 선수학습 학습지들을 참조한다.
4. 렌더러가 각 source에서 4문항씩 생성한다.
5. 진단용 compact 표현으로 변환한다.
6. 6개 source = 한 단 24문항, 12개 source = 한 장 48문항 기준으로 페이지를 나눈다.
7. 13개 source인 1단원은 1쪽 48문항 + 2쪽 4문항으로 만든다.

장점:

- 기존 선수학습 generator를 재사용한다.
- 원천 학습지가 바뀌면 진단지도 자연스럽게 따라간다.
- 진단지는 진단지답게 작고 촘촘하게 인쇄된다.
- 2단/48문항/2장 분할 규칙이 한곳에 모인다.

주의:

- 기존 `createSheet()`는 한 번에 한 장만 만든다. 진단지는 여러 장을 만들 수 있으므로 `app.js`에 작은 분기 처리가 필요하다.
- PDF형 선수학습은 기존 PDF 격자 렌더링 그대로 쓰면 너무 커질 수 있다. 진단지에서는 compact 식으로 변환해야 한다.

### 보수안: 단원별 진단지 generator를 하드코딩

단원별로 `genU1Diagnostic`, `genU2Diagnostic` 같은 함수를 새로 만든다.

장점:

- 구현이 단순하다.

단점:

- 기존 선수학습과 중복이 생긴다.
- 선수학습 항목이 바뀌면 진단지 generator도 따로 고쳐야 한다.
- 1단원처럼 52문항/2장 분할이 까다롭다.

### 비권장안: 기존 선수학습 학습지를 4문항씩 이어 붙이기

장점:

- 표시 로직 재사용이 쉬워 보인다.

단점:

- 세로셈/PDF/개념 카드가 너무 커서 한 단 24문항 기준을 지키기 어렵다.
- 페이지 수가 불필요하게 늘어날 가능성이 높다.

## 권장 구현 순서

1. `renderers.js`에 진단지용 compact 문제 변환 함수를 추가한다.
   - `vertical` 사칙연산 → 한 줄 식
   - `longdiv` → `나누어지는 수 ÷ 나누는 수 = □`
   - PDF division 데이터(`dvsr`, `dvnd`, `quot`, `rem`)도 한 줄 식으로 변환
   - 기존 `html` 문제는 내부 HTML을 재사용하되 진단지 CSS로 작게 표시
2. `renderers.js`에 `createDiagnosticSheets(item, fontScale)`를 추가한다.
   - source 1개 = 4문항 블록
   - 한 단 6개 source = 24문항
   - 한 장 12개 source = 48문항
   - 12개 source마다 새 A4 sheet 생성
3. `app.js`의 `generate()`에서 `item.kind === 'diagnostic'`이면 `createDiagnosticSheets()`를 사용하도록 분기한다.
   - 문제 수 입력은 진단지에서는 기본 총 문항 수를 사용한다.
   - 쪽수 입력은 “같은 진단지를 몇 부 만들지”로 해석하거나, 1로 고정하는 방안을 선택할 수 있다. 권장은 기존 흐름을 살려 쪽수만큼 같은 진단지를 반복 생성하는 것이다.
4. `g5-1.js`에 단원별 진단지 항목을 추가한다.
   - u1, u2, u4, u5, u6만 추가
   - u3은 선수학습이 없으므로 추가하지 않음
5. CSS에 진단지 전용 2단 레이아웃 추가
   - `.diagnostic-columns`
   - `.diagnostic-column`
   - `.diagnostic-block`
   - `.diagnostic-block-title`
   - `.diagnostic-problem`
6. 검증
   - `node .claude/scripts/validate.mjs 1000`
   - `node .claude/scripts/audit.mjs`
   - 로컬 브라우저에서 5-1 각 단원 진단지 확인
   - 특히 1단원은 2장으로 나뉘는지 확인
   - 정답 보기 전/후 확인
   - 인쇄 기준 A4 넘침 확인
7. `CHANGELOG.md` 기록
