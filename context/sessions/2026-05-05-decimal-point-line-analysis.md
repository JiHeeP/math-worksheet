# 분석 기록: 소수점 위치를 격자 칸 가운데에서 숫자 사이 선 위로 변경

- **일시**: 2026-05-05
- **요구사항 원문**: 소수의 곱셈과 나눗셈에서, 소수점을 한 칸의 중간에 찍고 있음. 소수점은 숫자와 숫자 사이 선에 찍혔으면 좋겠음.
- **판정**: ✅ 안전

## 영향 범위

| 대상 | 영향 수준 | 상세 |
|---|---:|---|
| `app/js/renderers.js` | 중간 | 현재 `decimalChars()`가 소수점 `.`을 하나의 문자/칸으로 분리하고, `decimalCell()`이 그 칸을 그대로 렌더링함. 소수점은 별도 칸이 아니라 앞 숫자 칸의 오른쪽 선 위에 붙여야 함. |
| `app/css/worksheet.css` | 중간 | `.decimal-dot-cell`은 소수점 칸 너비를 줄이는 방식임. 이를 선 위 표시용 span/위치 스타일로 바꿔야 함. |
| `app/js/app.js` | 낮음 | 자동 맞춤 측정에서 소수 격자 테이블 overflow 예외가 있음. 점 위치 변경 후에도 잘림 확인 필요. |
| `CHANGELOG.md` | 낮음 | 표시 버그 수정 기록 추가. |

## 점검 결과

| 점검 항목 | 결과 | 근거 |
|---|---|---|
| 기존 약속 | ✅ | 제너레이터의 문제 데이터나 학습지 ID는 바꾸지 않고, 렌더링 표시 방식만 바꾸면 됨. |
| 연결 관계 | ✅ | `renderers.js`와 CSS만 조정하므로 기존 `catalog → template/generator → renderer` 흐름을 유지함. |
| 데이터 모양 | ✅ | 저장 데이터/JSON 없음. 문제 객체의 `num1`, `num2`, `dvnd`, `quot` 값도 그대로 유지 가능. |
| 과거 기록 | ✅ | 정적 학습지라 과거 사용자 기록 재해석 위험 없음. |
| 사용자 흐름 | ✅ | 드롭다운, 문제 수, 정답 보기 흐름은 그대로 유지됨. |
| 되돌리기 어려움 | ✅ | 배포/삭제/인증 없음. JS/CSS 표시 수정만 해당. |

## 위반 상세

- 현재 소수점은 숫자와 같은 방식으로 `<td>` 하나를 차지한다.
- 이 때문에 격자에서 `7 . 9`처럼 소수점 전용 칸이 생겨, 사용자가 기대한 세로셈 자릿값 격자와 다르게 보인다.

## 제시한 대안

- **권장안**: 렌더러에서 소수점 전용 칸을 없애고, 앞 숫자 칸 오른쪽 경계선에 점을 올린다. 데이터 생성 규칙은 그대로 유지한다.
- **대안**: CSS만으로 `.decimal-dot-cell` 폭을 0에 가깝게 줄인다. 하지만 테이블 자릿수 계산과 정답 표시가 어색할 수 있어 비권장.
