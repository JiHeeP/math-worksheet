# 분석 기록: A4 한 장에 들어가는 최적 문제 수 산정

- **일시**: 2026-05-04
- **요구사항 원문**: 현재 문제지를 만들었을 때 가장 최적으로 많이 배치할 수 있는 문제수를 배치해야 한다. 더 많은 수를 배치해서 A4 한 장을 넘어가는 경우가 생긴다. 전체 학습지 중 일부를 확인하고 해결 방안을 3개 이상 가져와라.
- **판정**: ⚠️ 조건부 안전

## 확인한 현재 구조

| 대상 | 확인 내용 |
|---|---|
| `app/js/renderers.js` | `getWorksheetLimit()`은 실제 렌더링 높이가 아니라 `maxCols * maxRows`로만 최대 문제 수를 정함. |
| `app/js/layout.js` | `standard`, `practice`, `dense`, `concept`, `wide` 등 레이아웃별 최대 행/열만 있음. |
| `app/css/worksheet.css` | `.sheet`는 A4 고정 높이이며 `overflow: hidden`이라 넘친 내용은 잘릴 수 있음. |
| 카탈로그 | 기본 문제 수가 레이아웃 최대치와 같은 학습지가 많음. |

## 원인

- 현재 최대 문제 수는 “칸 수” 기준이라 실제 문제 내용 높이를 보지 않음.
- `.sheet`가 A4 고정 높이이고 `overflow: hidden`이라, 넘침이 발생하면 사용자가 출력에서 잘린 내용을 보게 됨.
- 글자 크기, 그림/분수/표/과정풀이 같은 문제 유형에 따라 같은 8문제/10문제/15문제라도 필요한 높이가 크게 달라짐.

## 해결 방안

| 방안 | 설명 | 장점 | 단점 |
|---|---|---|---|
| 1. 레이아웃별 안전 여백 적용 | `wide`, `concept`, `practice` 등 복잡한 레이아웃의 기본/최대 문제 수를 보수적으로 낮춤 | 빠르고 안전함 | 단순한 학습지는 공간을 덜 쓰게 됨 |
| 2. 학습지별 `fitCount` 메타 추가 | 각 학습지에 인쇄 안전 기본 문제 수를 별도로 기록 | 품질 관리가 쉬움, 중요한 학습지부터 조정 가능 | 새 학습지를 만들 때 메타 관리 필요 |
| 3. 렌더 후 자동 측정으로 문제 수 줄이기 | 실제 브라우저에서 만든 뒤 A4를 넘으면 문제 수를 하나씩 줄여 가장 많이 들어가는 수를 찾음 | 가장 정확함, 글자 크기와 실제 랜덤 문제까지 반영 | 구현 복잡도 높음, 생성 결과 안정성 관리 필요 |
| 4. 넘치면 자동으로 다음 페이지 분할 | 요청한 문제 수를 유지하되 한 장에 안 들어가면 다음 장으로 넘김 | 문제 누락 없음, 잘림 없음 | “한 장에 최대로”라는 요구와는 다를 수 있음 |
| 5. 측정 기반 입력 제한/경고 | 사용자가 문제 수를 많이 넣으면 현재 학습지/글자크기 기준 안전 최대값으로 낮추거나 안내 | 사용자 실수를 막음 | 자동 측정 로직과 함께 써야 효과가 큼 |

## 권장안

1차 구현은 **방안 3 + 방안 5** 조합이 가장 요구에 맞음.

- 기본 생성 시 실제 DOM 높이를 측정해서 A4 한 장에 들어가는 최대 문제 수를 자동 산정.
- 문제 수 입력의 최대값도 해당 산정값으로 제한.
- 측정 실패나 예외 상황에서는 방안 2의 `fitCount`를 fallback으로 사용.
