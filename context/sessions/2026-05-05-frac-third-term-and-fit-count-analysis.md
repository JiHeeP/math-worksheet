# 분석 기록: 분수 계산 과정 3번째 중간항 정리와 1문항 배치 오류 해결

- **일시**: 2026-05-05
- **요구사항 원문**: 1. 2열 배열 취소 - 이건 지워라. 2. 분수의 곱셈과 나눗셈 계산과정 익히는 학습지들에서 3번째 중간항이 불필요한 학습지 내역들을 분석하라. 3. 1개밖에 안 들어가는 학습지 문제는 해결해야 한다. 2번을 먼저 작업한 후, 2번과 3번을 한꺼번에 해결하라.
- **판정**: ✅ 안전

## 이번 범위

- 2열 배치 변경은 **작업 범위에서 제외**한다.
- 먼저 분수 곱셈/나눗셈 계산 과정의 3번째 중간항을 정리한다.
- 그 다음 1문항으로 떨어지는 자동 문제 수 산정 오류를 함께 고친다.

## 2번 분석: 3번째 중간항이 불필요한 학습지

현재 분수 곱셈/나눗셈 계산 과정은 모두 4항 구조다.

```text
원식 = 변환식/전개식 = 계산된 중간 분수 = 최종답
```

또는

```text
원식 = 역수 곱셈식 = 분자끼리·분모끼리 곱하는 식 = 최종답
```

실제 샘플을 생성해 보니 다음 13개 학습지에서 모두 3번째 항이 최종답 직전의 중간항으로 나온다.

| 학년·학기 | 학습지 | 현재 3번째 항 성격 | 판단 |
|---|---|---|---|
| 5-2 | `(진분수) × (자연수) 계산 과정` | 약분/대분수 변환 전 분수 | 삭제 가능 |
| 5-2 | `(대분수) × (자연수) 계산 과정` | 가분수 변환 뒤 곱셈 전개식 | 삭제 가능 |
| 5-2 | `(자연수) × (진분수) 계산 과정` | 약분/대분수 변환 전 분수 | 삭제 가능 |
| 5-2 | `(자연수) × (대분수) 계산 과정` | 가분수 변환 뒤 곱셈 전개식 | 삭제 가능 |
| 5-2 | `(단위분수) × (단위분수) 계산 과정` | 계산된 중간 분수 | **삭제 권장**: 최종답과 항상 사실상 중복 |
| 5-2 | `(진분수) × (진분수) 계산 과정` | 약분 전 분수 | 삭제 가능 |
| 5-2 | `(대분수) × (대분수) 계산 과정` | 가분수 변환 뒤 곱셈 전개식 | 삭제 가능 |
| 6-1 | `(자연수) ÷ (자연수) 계산 과정` | 곱셈 전개식 | **삭제 권장**: `a/1 × 1/b` 다음에 바로 `a/b`로 가도 충분 |
| 6-1 | `(진분수) ÷ (자연수) 계산 과정` | 곱셈 전개식 | 삭제 가능 |
| 6-1 | `(대분수) ÷ (자연수) 계산 과정` | 곱셈 전개식 | 삭제 가능 |
| 6-2 | `(진분수) ÷ (진분수) 계산 과정` | 곱셈 전개식 | 삭제 가능 |
| 6-2 | `(자연수) ÷ (진분수) 계산 과정` | 곱셈 전개식 | 삭제 가능 |
| 6-2 | `(대분수) ÷ (진분수) 계산 과정` | 곱셈 전개식 | 삭제 가능 |

### 결론

- 13개 모두 3번째 항을 없애도 계산 흐름은 유지된다.
- 가장 불필요한 것은 `단위분수 × 단위분수`, `(자연수) ÷ (자연수) 계산 과정`이다.
- 나머지도 “전개식 → 최종답” 사이에서 종종 식이 길어지고 한 줄이 복잡해지는 원인이므로, 이번 요청 의도에 맞게 13개 전체에서 일괄 제거하는 것이 좋다.
- 구현은 `templates.js`의 공통 템플릿 2개만 바꾸면 된다.

## 3번 분석: 1문항으로 떨어지는 문제

Chrome headless에서 실제 앱을 1200px 데스크톱 폭으로 열고 전체 244개 학습지를 측정했다.

- 안전 문제 수가 1로 떨어지는 학습지: 18개
- 모두 카탈로그 `count`가 1인 것이 아니라, 자동 맞춤 검사 실패 후 fallback 1이 된 경우다.

| 학습지 | 현재 안전 문제 수 |
|---|---:|
| 1-2 `10의 보수 (가로셈 빈칸)` | 1 |
| 1-2 `한 자리 수 + 한 자리 수(받아올림) - 가로` | 1 |
| 1-2 `십몇 - 몇(받아내림) - 가로` | 1 |
| 2-1 `두 자리 수 - 한 자리 수(받아내림) - 연습 2` | 1 |
| 2-1 `두 자리 수 - 두 자리 수(받아내림) - 연습 2` | 1 |
| 2-2 곱셈구구 `2단~9단`, `기본`, `혼합` | 1 |
| 3-1 `나눗셈 (한 자리 나누기)` | 1 |
| 5-1 선수학습 `곱셈구구`, `나눗셈 (한 자리 나누기)` | 1 |

확인한 원인:

- `app/js/app.js`의 `createFittedSheet()`가 최대 문제 수부터 줄여 보다가 모두 실패하면 `count: 1` fallback을 반환한다.
- `.horiz-box` 줄바꿈 판정이 `rect.height > oneLineLimit`를 사용한다. 그런데 정답 네모칸 자체가 한 줄 높이를 키워서, 실제로 줄바꿈이 없어도 “줄바꿈”으로 오판될 수 있다.
- `origin-borrow-v2` 유형은 1문항에서도 `scrollHeight > clientHeight`가 감지된다. 실제 출력보다 CSS 박스 내부 측정이 더 크게 잡히는 쪽이다.
