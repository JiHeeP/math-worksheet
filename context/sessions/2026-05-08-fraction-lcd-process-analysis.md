## 현재 상태 요약

- `app/js/generators/g5-1/u4.js`의 `pickLcdPair()`는 현재 `d1 !== d2`만 보장한다. 따라서 `5`와 `7`처럼 서로소인 분모가 나올 수 있고, 이 경우 최소공배수는 두 분모의 곱과 같다.
- `app/js/generators/g5-1/u5.js`의 `genFracAddLt1`, `genFracAddGe1`, `genFracSub`, `genMixedAddNoCarry`, `genMixedAddCarry`, `genMixedSubNoBorrow`, `genMixedSubBorrow`도 같은 방식으로 임의의 서로 다른 분모를 고른다.
- `app/js/templates.js`의 `inlineFracAdd()` / `inlineFracSub()`는 통분 뒤 분수의 분모에 `common`을 그대로 보여준다.
- `inlineMixedAddImproper()` / `inlineMixedSubImproper()`는 대분수를 가분수로 바꾼 뒤, 곱하는 과정을 생략하고 바로 공통분모 결과로 넘어간다.
- `inlineMixedAddSeparate()` / `inlineMixedSubSeparate()`는 자연수/분수 따로 풀이에서 `fracExpand()`를 통해 곱하는 과정을 보여주지만, 같은 줄에서 바로 공통분모 계산까지 이어져 있어 사용자가 말한 “3번째 계산 과정”으로 분리되어 있지는 않다.

## 세부 해석

### 1. 최소공배수가 두 수의 곱보다 작게

- 수학적으로 `lcm(d1,d2) < d1*d2`는 두 분모가 서로소가 아니라는 뜻이다.
- 구현 조건은 `gcd(d1,d2) > 1`로 두는 것이 가장 명확하다.
- 분모가 같으면 통분 문제가 아니므로 `d1 !== d2`는 계속 유지한다.

### 2. 분모를 미리 제시하지 않기

- 문제지 화면에서는 통분 후 분모 숫자를 직접 보여주지 않는다.
- 단, 정답 보기에서는 현재 앱 구조상 한 가지 예시 풀이가 드러나야 하므로, 최소공배수를 `data-ans`로 둔 빈칸을 표시하는 방식이 적절하다.
- 학생이 다른 공통분모를 선택할 수 있다는 점 때문에, UI 문구를 추가하기보다는 “빈칸”으로 열어 두는 편이 현재 중복 정보 금지 원칙과 잘 맞는다.

### 3. 대분수 덧셈·뺄셈 단계 추가

- 가분수 변환 방식과 자연수·분수 따로 방식 모두 영향을 받는다.
- 특히 현재 가분수 변환 방식은 곱하는 과정을 생략하므로 요구사항과 차이가 크다.
- 자연수·분수 따로 방식은 곱하는 과정이 이미 있으나 한 줄 안에 합쳐져 있어, “3번째 계산 과정”으로 분리하는 변경이 필요하다.

## 주의할 점

- 대분수 풀이가 길어지면 현재 `grid: 'wide', count: 8`이어도 일부 단계가 빽빽해질 수 있다. CSS만으로 해결이 어려우면 해당 템플릿의 기본 문제 수를 줄이는 선택지도 검토해야 한다.
- `fracBlank(common)`을 쓰면 정답 보기 전에는 값이 숨겨지지만, 정답 보기 후에는 “최소공배수 기준 예시 답”이 보인다. 학생이 다른 공통분모를 쓸 수 있다는 교육적 여지는 남기되, 교사용 정답은 하나의 예시로 제시하는 구조다.
- `u4.js`는 일부 generator가 HTML을 직접 만든다. 당장 구조 전체를 바꾸기보다, 이번 변경에 필요한 범위만 조심스럽게 수정하는 편이 안전하다.
